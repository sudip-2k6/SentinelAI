# Contributing to SentinelAI

Start with [the development guide](docs/DEVELOPMENT.md). Use generated fixtures
for scanner tests and keep live samples, personal paths, and scan databases
out of public issues and pull requests.

- Open issues with the app version, operating system, expected behavior, and
  steps to reproduce. Include sanitized logs or an inert fixture when useful.
- Keep pull requests focused. For changes to classification or scoring, include
  dataset provenance, evaluation methodology, and observed metrics.
- Run Ruff, mypy, and pytest before opening a pull request. For UI changes,
  include screenshots or notes for both themes when relevant.

See [the scanner's security model](docs/SECURITY.md).
